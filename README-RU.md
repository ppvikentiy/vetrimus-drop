# Vetrimus Drop

Веб-сервис передачи файлов без создания учётных записей.

Клиент выполняет шифрование каждой раздачи до передачи на сервер. Сервер сохраняет шифртекст в S3-совместимом бакете. PostgreSQL хранит хэши и служебные записи. URL раздачи имеет вид `https://хост/<токен>#<ключ>`, где `<токен>` состоит из 43 символов. Ключ размещается во фрагменте URL и в HTTP-запросы не включается.

English edition: [README.md](README.md).

## Предельные значения

- Максимальное число файлов в одной раздаче: 10.
- Максимальный размер одного файла: 500 МБ.
- Срок хранения, отсчитываемый от публикации: 1, 3, 7 или 30 суток.
- Лимит скачиваний: 1, 5, 10 либо целое число в диапазоне 1..1000.
- Пароль: необязателен. До успешной проверки тело ответа API содержит только `requiresPassword`. Список файлов и ключ доступа не возвращаются.
- Несколько файлов извлекаются по отдельности либо собираются в ZIP в браузере получателя. Одиночный файл поддерживает HTTP Range.
- Миниатюры изображений и видео представляют собой объекты JPEG размером не более 40 КБ. Они формируются в браузере отправителя и включаются в зашифрованный блок описания. Отображение миниатюры счётчик скачиваний не увеличивает.
- Отправитель может удалить раздачу сразу. Секрет загрузки остаётся в браузере около 6 часов: на странице после публикации и при следующем открытии.
- В Chrome на Android отправка продолжается после закрытия приложения (Background Fetch). Ссылка показывается при следующем открытии.

Раздачи с истёкшим `expires_at` и раздачи с `download_count >= max_downloads` удаляются из объектного хранилища и из базы данных задачей с периодом 10 минут. Удаление откладывается на 24 часа после `last_download_at`, что допускает завершение прерванного запроса Range.

## Маршруты

| Путь | Назначение |
| --- | --- |
| `/home` | Начальная страница. `GET /` возвращает перенаправление на `/home`. В автономном режиме отображения клиент заменяет `/home` на `/upload`, если навигатор сообщает о наличии сети. |
| `/upload` | Выбор файлов и публикация. Параметры: срок хранения, лимит скачиваний, необязательный пароль. |
| `/<токен>` | Страница получения. Токен соответствует выражению `^[A-Za-z0-9_-]{43}$`. |
| `/receive` | Сопряжение для узла без камеры. Страница отображает короткий код и символ QR. |
| `/p/<код>` | URL сопряжения, закодированный в этом символе. Клиент заменяет путь на `/upload?pair=<код>` и сохраняет фрагмент. |
| `/offline` | Оптическая передача без сети. Передача: `/offline/send`. Приём: `/offline/receive`. |
| `/policy` | Политика обработки данных. Текст перечисляет категории данных, сохраняемые реализацией. |

Вне автономного режима отображения маршруты `/upload`, `/receive`, `/offline` (включая дочерние) и `/<токен>` не отображаются до фиксации состояния согласия `accepted`. Значение хранится в `localStorage` по ключу `vd-consent`. В автономном режиме элемент согласия не выводится.

Идентификаторы оформления: `dark`, `light`, `simple`. Значение `simple` задаёт увеличенный кегль, отключение анимации, пошаговые подписи и видимую обводку основного действия. Выбор хранится по ключу `vd-theme`. При отсутствии сохранённого значения `prefers-color-scheme: light` выбирает `light`; в остальных случаях клиент выбирает `dark`.

Язык интерфейса — русский. Оформление по умолчанию — тёмная моноширинная вёрстка. В сборку клиента включены гарнитуры JetBrains Mono и Inter.

## Шифрование

Раздачи, создаваемые опубликованным клиентом, шифруются в браузере отправителя. Формат — VDE1. Спецификация: [client/src/crypto/VDE-RU.md](client/src/crypto/VDE-RU.md). English edition: [client/src/crypto/VDE.md](client/src/crypto/VDE.md). Реализация: `client/src/crypto/vde.js`. Команда тестирования: `cd client && npm test`.

- Мастер-ключ: 256 бит, CSPRNG, одно значение на раздачу. Кодирование: base64url без дополнения (43 символа). Размещение: фрагмент URL после `#`.
- Вывод ключей: HKDF-SHA-256, пустая соль. Info ключа описания: `vde1 meta`. Info ключа файла: `vde1 file N`, где `N` — индекс файла с нуля.
- Имена, медиатипы, размеры открытого текста и миниатюры содержатся в зашифрованном блоке описания. Имена файлов в базе данных — заполнители `file-0`, `file-1` и далее. В базе хранятся длины шифртекста.
- Service worker получателя запрашивает шифртекст с HTTP Range, расшифровывает сегменты по 1 МиБ и может сформировать ZIP средствами `client-zip`. Если worker не управляет страницей, расшифрование выполняется в памяти страницы.

Пароль является серверным предикатом доступа к списку. В вывод ключей он не входит. `POST /api/drops` отклоняет пароль при наличии `pairCode`: мастер-ключ уже присутствует во фрагменте URL сопряжения.

Отсутствие фрагмента исключает расшифрование. Обладание полным URL достаточно для расшифрования. Подменённое клиентское приложение может прочитать ключ в браузере. Установка PWA и воспроизводимая сборка снижают подверженность подмене отдаваемого приложения. Раскрытие базы данных или бакета не раскрывает имён и открытого текста.

## Сопряжение

`/receive` — страница сопряжения для узла, не использующего камеру. Страница выполняет `POST /api/pair` и отображает код вида `K7M-4QX-9TD` и символ QR с полезной нагрузкой `/p/<код>#<ключ>`. Узел формирует мастер-ключ и помещает его только во фрагмент.

Отправляющий клиент открывает этот URL, шифрует ключом из фрагмента и передаёт раздачу с полем `pairCode` в `POST /api/drops`. Принимающий узел опрашивает `GET /api/pair/:code/status` с заголовком `X-Pair-Secret`. В состоянии `ready` узел переходит на `/<токен>#<ключ>`.

- Алфавит кода: Crockford base32, длина 9, энтропия 45 бит. Регистр и символы-разделители при нормализации отбрасываются. Хранимое значение — `SHA-256` от префикса `pair:`, соединённого с нормализованным кодом.
- Срок до присоединения: 10 минут. Срок после присоединения: равен сроку незавершённой раздачи, 6 часов. Открытый токен сохраняется для получения не дольше 15 минут, после чего строка сопряжения удаляется.
- Неуспешные проверки кода: 20 за 15 минут с одного IP-адреса. Создание кодов: 30 в час с одного IP-адреса.

## Оптическая передача

Один файл размером не более 256 МиБ передаётся последовательностью символов QR с дисплея на камеру. Канал не имеет сетевого пути и обратного пути. Кодек — пакет `vqd`. Описание: [vqd/README-RU.md](vqd/README-RU.md). Формат: [vqd/SPEC-RU.md](vqd/SPEC-RU.md). English editions: [vqd/README.md](vqd/README.md), [vqd/SPEC.md](vqd/SPEC.md). Эксплуатационная граница порядка 150 МиБ определена по измерениям.

Отправитель выбирает версию QR 40, 30 или 20 и частоту кадров в диапазоне 5..30 кадров в секунду. Получатель декодирует средствами zxing-wasm в worker и записывает принятые байты в OPFS. Приём сохраняется при перезагрузке страницы. На устройстве удерживается одна незавершённая передача. Каждый сегмент проверяется SHA-256. Потеря, повтор, перестановка кадров и позднее подключение допускаются фонтанным кодом.

При установке service worker выполняет предварительное кэширование оболочки приложения, включая декодер WebAssembly. После одной загрузки при наличии сети оптические маршруты функционируют без сети. Доступ к камере ограничен заголовком `Permissions-Policy: camera=(self)`. В этом режиме шифрование не применяется. Камера, наблюдающая дисплей, получает файл.

## Установленное приложение

Сайт является прогрессивным веб-приложением. Если браузер предоставляет запрос на установку, подвал отображает соответствующий элемент управления. На iOS подвал фиксирует последовательность Safari: «Поделиться», затем «На экран Домой».

После установки цель общего доступа Android доставляет файлы на `/upload`. Service worker обрабатывает `POST /share-target`. Если worker ещё не управляет клиентом, сервер отвечает на этот URL перенаправлением на `/upload`.

При сообщении навигатора об отсутствии сети оболочка отдаётся из кэша, а информационная полоса содержит ссылку на оптическую передачу. Ответы API и тела файлов в кэш не помещаются. Ответы документов используют `Cache-Control: no-cache`. Файлы в `/assets/` кэшируются как неизменяемые в течение одного года. `sw.js` и веб-манифест используют `Cache-Control: no-cache`.

Поля манифеста `handle_links` и `launch_handler` запрашивают открытие URL Drop в установленном приложении на Android и в настольном Chromium. Safari на iOS для веб-приложений это поведение не реализует.

## Идентификация сборки

Подвал отображает версию из `client/package.json`, тип сборки (`release` или `dev`), номер сборки и, при наличии, краткий идентификатор коммита. Номер берётся из `BUILD_NUMBER`, иначе из `client/build-info.json` (файл записывает `deploy.ps1` при наличии git), иначе из `git rev-list --count HEAD`, иначе из метки времени UTC вида `YYYYMMDD.HHMM`. Тип равен `release` для производственной сборки Vite и `dev` в остальных случаях, если не задана переменная `BUILD_TYPE`. Идентификатор коммита берётся из `GIT_SHA`, иначе из того же JSON-файла, иначе из `git rev-parse --short HEAD`.

## Состав репозитория

```
браузер → nginx :80/:443 → Node.js (Express, 127.0.0.1:3000) → бакет S3
                                      │
                                      └── PostgreSQL (раздачи, лимиты, хэши паролей)
```

| Каталог | Содержимое |
| --- | --- |
| `client/` | Интерфейс на React 18 и Vite, service worker, VDE |
| `server/` | API на Express, потоковая запись в S3, PostgreSQL, очистка |
| `vqd/` | Фонтанный кодек кадров QR, Apache-2.0, без интерфейса |
| `deploy/` | `deploy.bat` и `deploy.ps1` для Windows; `install.sh` для сервера |

Байты объекта передаются через API в бакет потоком. Файловая система сервера копию не сохраняет. Пароли хранятся в виде хэшей scrypt с параметрами `N=16384`, `r=8`, `p=1`, солью длиной 16 байт и производным ключом длиной 64 байта. Представление в базе данных: `scrypt$<соль>$<ключ>`, обе компоненты в base64.

## Развёртывание с Windows

Входные условия: VPS под управлением Ubuntu или Debian с доступом по SSH, S3-совместимый бакет и, при необходимости, домен, A-запись которого разрешается в адрес сервера. На узле оператора требуются Windows 10 или Windows 11 и клиент OpenSSH.

`deploy\deploy.bat` принимает конечную точку SSH, необязательные домен и адрес электронной почты для Let's Encrypt, а также endpoint, регион, имя бакета и учётные данные S3. Пустые домен и адрес электронной почты оставляют сервис доступным по IP-адресу.

Скрипт проверяет SSH. Аутентификация по паролю приводит к установке ключа `%USERPROFILE%\.ssh\vetrimus_deploy_ed25519`. Затем скрипт передаёт дерево файлов и выполняет `deploy/install.sh`. Установщик разворачивает nginx, PostgreSQL и Node.js. Node.js 22 устанавливается, если текущая мажорная версия ниже 20. Роль базы данных создаётся только при отсутствии. Выполняется сборка клиента. Проверяются запись в бакет и удаление из бакета. Устанавливается unit systemd `vetrimus-drop`. Записывается сайт nginx `vetrimus-drop`. При заданных домене и адресе электронной почты сертификат запрашивается командой `certbot certonly --nginx --keep-until-expiring`. Сертификат, находящийся внутри срока действия, не заменяется.

Повторное выполнение применяет изменения и сохраняет существующие пароль базы данных и `APP_SECRET`. Конфигурация nginx, которой управляет установщик, ограничена сайтом `vetrimus-drop`. Заданный домен не устанавливает `default_server`. Обслуживание по IP-адресу устанавливает `default_server` только при отсутствии этого флага у другого сайта. Путь журнала установки: `/var/log/vetrimus-drop-install.log`. Собранные параметры, за исключением секретного ключа S3, сохраняются в `deploy/deploy.settings.json`.

```bash
systemctl status vetrimus-drop
journalctl -u vetrimus-drop -f
cat /opt/vetrimus-drop/.env
```

Политика жизненного цикла бакета должна прерывать незавершённые multipart-загрузки по истечении одних суток. В противном случае части загрузки, прерванной завершением процесса, остаются в бакете.

## Локальная разработка

Требования: Node.js версии 20.6 или новее, PostgreSQL и S3-совместимая конечная точка. MinIO удовлетворяет требованию к хранилищу.

```bash
cd server
cp .env.example .env
npm install
npm run check-s3
npm run dev
```

API принимает соединения на `http://127.0.0.1:3000`. Миграция схемы выполняется при старте процесса.

```bash
cd client
npm install
npm run dev
```

Интерфейс обслуживается по адресу `http://localhost:5173`. Запросы с префиксом `/api` проксируются на процесс API.

`server/.env.example` определяет `DATABASE_URL`, `APP_SECRET`, `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` и `S3_FORCE_PATH_STYLE`. `PORT` и `HOST` необязательны.

## HTTP API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | Тело ответа `{ ok: true }`. |
| `POST /api/drops` | Создаёт незавершённую раздачу. Тело JSON: `files` — массив `{ size, name?, thumb? }`, `expiry` из множества `{1d, 3d, 7d, 30d}`, `maxDownloads`, необязательный `password`, `enc: true` с `meta` в base64, необязательный `pairCode`. |
| `GET /api/drops/:id/files/:fileId/status` | Возвращает число сохранённых байт. Требуется заголовок `X-Upload-Secret`. |
| `PUT /api/drops/:id/files/:fileId` | Записывает байты объекта. Частичная запись использует `Content-Range: bytes START-END/SIZE`. Тело, покрывающее объект целиком, передаётся потоком без этого заголовка. Требуется `X-Upload-Secret`. |
| `POST /api/drops/:id/finalize` | Публикует незавершённую раздачу и возвращает публичный токен. Повторный вызов после публикации отвечает кодом 409. |
| `DELETE /api/drops/:id` | Удаляет незавершённую или опубликованную раздачу. Требуется `X-Upload-Secret`. Успешный код — 204. Неизвестный идентификатор или несовпавший секрет дают код 404. |
| `GET /api/d/:token` | Возвращает метаданные раздачи либо `{ requiresPassword: true }`. |
| `POST /api/d/:token/unlock` | Проверяет пароль и возвращает список файлов и ключ доступа. |
| `GET /api/d/:token/files/:index?key=` | Возвращает один объект шифртекста. Поддерживает HTTP Range. |
| `GET /api/d/:token/download?key=` | Возвращает ZIP или один файл для раздачи с `enc`, равным false. Раздача с `enc`, равным true, отвечает кодом 409. Расшифрование использует `/files/:index`. |
| `GET /api/d/:token/thumbs/:index?key=` | Возвращает миниатюру JPEG. Определён только для раздачи с `enc`, равным false. |
| `POST /api/pair` | Выделяет код сопряжения и секрет. |
| `GET /api/pair/:code/check` | Сообщает, находится ли код в состоянии `waiting`. |
| `GET /api/pair/:code/status` | Возвращает `waiting`, `uploading` или `ready` с токеном. Требуется заголовок `X-Pair-Secret`. |
| `DELETE /api/pair/:code` | Удаляет строку сопряжения. Требуется `X-Pair-Secret`. |

Опубликованный клиент устанавливает `enc` в `true` в каждом запросе создания. API принимает запрос создания, в котором `enc` не равен `true`, и в этом случае сохраняет очищенное имя файла и необязательную миниатюру. Опубликованный интерфейс такой запрос не формирует.

**Учёт скачиваний.** Открытие страницы или успешное снятие пароля возвращает ключ доступа: HMAC-SHA256 на ключе `APP_SECRET`, срок действия 24 часа, содержит случайный nonce. Первый запрос, предъявляющий ранее не наблюдавшийся ключ, увеличивает `download_count` на единицу. Последующие запросы с тем же ключом в течение 24 часов, включая продолжение Range, дополнительные файлы и получение ZIP, счётчик не увеличивают. К IP-адресу ключ не привязан.

**Продолжение загрузки.** Объекты размером более 5 МиБ передаются частями по 8 МиБ через multipart-загрузку S3. Сервер отклоняет нефинальную часть размером менее 5 МиБ и частичную часть размером более 32 МиБ. `PUT`, диапазон которого покрывает объект целиком, передаётся потоком при любом размере в пределах лимита раздачи и не буферизуется как одна часть. Если для этого объекта уже открыта multipart-загрузка, она прерывается до приёма потока. `PUT` файла, уже помеченного как загруженный, подтверждается как успех, а тело отбрасывается. Частичный `PUT`, начальное смещение которого не равно сохранённому `uploaded_bytes`, отвечает кодом 409 и текущим смещением. Клиент сохраняет `dropId`, секрет загрузки, мастер-ключ и смещения по файлам в IndexedDB (`vd-uploads`). После сбоя транспорта клиент возобновляет запись с сохранённого смещения. Повторное открытие документа при ещё существующей записи выводит запрос на продолжение при выборе тех же файлов. Незавершённая раздача, не прошедшая финализацию, истекает на сервере через 6 часов. Клиент удаляет записи IndexedDB, у которых `updatedAt` старше 7 часов.

**Гонка публикации.** Страница и service worker могут оба вызвать `POST /api/drops/:id/finalize`. Первый вызов, заставший `status = 'pending'`, публикует раздачу. Последующий вызов получает код 409. Вызвавший, получивший 409, читает токен из записи IndexedDB, которую записал победитель (`waitForReady`, тайм-аут 10 секунд).

**Фоновая отправка.** Путь используется только в Chrome на Android и только при наличии `BackgroundFetchManager`, управляющего service worker и origin-private file system, а также когда `navigator.storage.estimate` сообщает не менее `2 × длина шифртекста + 8 МиБ` свободной квоты. Страница шифрует каждый файл в OPFS, удерживая в памяти один сегмент, в каталог, удаляемый после публикации. Затем она передаёт по одному `PUT` целого объекта на файл через Background Fetch. Идентификатор регистрации равен `dropId`. Браузер может продолжить передачу после закрытия документа. По событию `backgroundfetchsuccess` service worker вызывает финализацию, удаляет каталог шифртекста и отправляет открытым окнам сообщение `vd-bg-ready`. По событию `backgroundfetchfail` заголовок уведомления устанавливается в строку сбоя. `backgroundfetchclick` открывает `/upload`. Если фоновую регистрацию начать нельзя, страница выполняет загрузку, пока документ открыт. Прочие агенты пользователя выполняют загрузку только при открытом документе.

**Удаление отправителем.** `DELETE /api/drops/:id` с заголовком `X-Upload-Secret` удаляет объекты бакета и затем строку базы данных, не дожидаясь срока или лимита скачиваний. Сравниваемое значение — `SHA-256` секрета загрузки. Удаление объекта является строгим: если хранилище не подтвердило удаление, строка сохраняется и запрос допускается повторить. Клиент трактует коды 204 и 404 как завершение и затем удаляет запись IndexedDB и каталог шифртекста в OPFS. После публикации локальная запись, а вместе с ней элемент удаления, сохраняется до отсечения по `updatedAt` в 7 часов.

**Заголовки ответа.** `Content-Security-Policy` разрешает `'wasm-unsafe-eval'` в `script-src` для декодера QR. Дополнительные заголовки: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin` и `Permissions-Policy` с `camera=(self)`. Ответы по HTTPS содержат `Strict-Transport-Security`. Ответы на скачивание устанавливают сохранённый медиатип и `Content-Disposition: attachment`.

**Ограничения частоты, на один IP-адрес.** Создание раздач: 30 в час. Создание кодов сопряжения: 30 в час. Проверка пароля: 20 за 15 минут. Неуспешные проверки кода сопряжения: 20 за 15 минут. Запросы состояния сопряжения: 300 в минуту.

Индексируемые пути документов: `/home`, `/upload`, `/receive`, `/offline`, `/offline/send`, `/offline/receive`, `/policy`. Прочие ответы HTML, включая URL раздач, содержат `X-Robots-Tag: noindex`.
