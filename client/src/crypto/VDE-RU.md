# VDE1

Vetrimus Drop Encryption, версия 1. Браузер отправителя шифрует раздачу. Сервер хранит шифртекст и ключ не получает.

English edition: [VDE.md](VDE.md). Реализация: [`vde.js`](vde.js). Тесты: `client/test/vde.test.js`. Команда: `npm test` в каталоге `client/`.

## Мастер-ключ

Каждая раздача имеет один мастер-ключ длиной 256 бит (`KEY_BYTES = 32`), полученный из CSPRNG. Ключ переносится только во фрагменте URL:

```
https://хост/<токен>#<ключ>
```

`<ключ>` — кодирование base64url указанных 32 байт без дополнения `=`. Длина равна 43 символам. HTTP-клиенты фрагмент не передают. `keyToString` и `keyFromString` выполняют преобразование между сырым ключом и этим кодированием. Вход, который не декодируется ровно в 32 байта, отклоняется.

## Производные ключи

Вывод выполняется функцией HKDF-SHA-256 с пустой солью. Результат — ключ AES-256-GCM.

| Назначение | Info для HKDF |
| --- | --- |
| Блок описания | `vde1 meta` |
| Индекс файла `i`, с нуля | `vde1 file <i>` |

`i` кодируется как беззнаковое 32-битное целое (`index >>> 0`). Ключ файла является функцией индекса файла. Подстановка шифртекста между позициями не проходит проверку подлинности.

## Сегменты

Открытый текст разбивается на сегменты длины `SEG = 1 МиБ` (`SEGMENT_SIZE`). Заключительный сегмент может иметь меньшую длину. Пустой открытый текст занимает один сегмент и поэтому содержит метку подлинности.

Каждый сегмент шифруется AES-256-GCM.

- Nonce, 12 байт: четыре байта `0x00`, затем индекс сегмента как big-endian `uint64` в оставшихся восьми байтах. Реализация записывает индекс вызовом `DataView.setUint32` со смещения 8. Устанавливаются только младшие 32 бита. Старшие 32 бита остаются нулевыми. Уникальность обеспечивается тем, что каждый файл использует отдельный ключ.
- Дополнительно аутентифицируемые данные, 1 байт: `0x01` для заключительного сегмента потока, иначе `0x00`.
- Шифртекст: открытый текст, соединённый с 16-байтовой меткой GCM.

Расшифрование завершается ошибкой при неверном ключе, изменённом бите, переставленном сегменте, повторённом сегменте, удалённом сегменте, добавленном сегменте, а также при шифртексте, взятом из другой раздачи или с другого индекса файла. При изменении потока изменяются и флаг заключительного сегмента, и индекс сегмента.

```
ciphertextLength(n) = n + 16 * ceil(max(1, n) / SEG)
```

`plaintextLength` является обратной функцией. Длина шифртекста, кратная `1 МиБ + 16`, обозначает последовательность полных сегментов. Любой иной остаток должен иметь длину не менее 16, равную длине метки. Более короткий остаток не является допустимой длиной шифртекста.

Полный сегмент на проводе занимает `CIPHER_SEGMENT_SIZE = 1 МиБ + 16` байт.

## Блок описания

Блок описания представляет собой JSON в кодировке UTF-8, зашифрованный ключом описания и передаваемый на сервер в стандартном base64 (`bytesToBase64`).

```json
{ "v": 1, "files": [{ "name": "...", "type": "...", "size": 0, "thumb": "data:image/jpeg;base64,..." }] }
```

Член `thumb` необязателен. Сервер сохраняет шифртекст в `drops.meta_ct` и разбор не выполняет. В базе данных для файлов сохраняются только имена-заполнители `file-N` и длины шифртекста.

## Поля, наблюдаемые сервером

Сервер наблюдает число файлов, длину шифртекста каждого файла, метки времени, срок хранения, счётчик скачиваний и наличие хэша пароля. Сервер не наблюдает имён, медиатипов, миниатюр и байтов открытого текста.

## Модель угроз

VDE1 обеспечивает конфиденциальность содержимого и имён по отношению к оператору, объектному хранилищу и стороне, получившей хранимые записи. Конфиденциальность не сохраняется для стороны, получившей полный URL, поскольку ключ содержится в URL. Конфиденциальность не сохраняется в отношении подменённого веб-приложения, читающего ключ в браузере. Версия 1 не определяет функцию вывода ключа из пароля. Пароль раздачи является исключительно серверным замком списка.
